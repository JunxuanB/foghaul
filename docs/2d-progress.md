## 三、界面重做第一轮：改了什么

负责人的反馈：“还缺 `<g>杯子×1</g>` 直接显示了代码”；“岛屿产能升级的界面没有主次、看不清楚”；“所有 UI 忽上忽下，大小应该恒定”；“星露谷的界面统一、类似功能的页面一致、画面驱动；你现在还是文字驱动的”。

| 问题 | 原因 | 现在 |
| --- | --- | --- |
| 显示 `<g>` 标记 | 文字版的富文本句子被 `tm()` 当纯文字放进界面 | 界面用的键不许有标记，规则层原因用 `reasonText()`、名字用 `label()`；`tests/uiText.test.ts` 检查词典和 `src/ui` 源码 |
| 文字驱动 | 面板是一列“标签：文字”，花费、缺料、需求都是一句话 | `Kit` 零件：图标格（有 / 要，够了打勾、不够红框）、碗、星、头像、建筑图、状态条；新加一组 `ui_*` 界面图标 |
| 面板忽大忽小、各写一套 | 外框高度随内容变，两种宽度；同类页面布局不同 | 一种固定大小的外框（320 × 200），头 / 身 / 底栏位置固定，主按钮永远在右下；四个模板 |
| 设施面板没有主次 | 所有信息同样大小排成一列 | 左边设施的图和星；右边①产出（大图标、每小时、仓库条、运转 / 停工原因）②工人头像格 ③升级卡（6 个碗、材料格、现在 → 以后）；底栏写还差什么，按钮“升到 N 级” |
| HUD 跳动 | 目标卡、提示卡、日志随字数变高 | 三者固定高度，多出的字截掉（完整内容在日志 J 里） |
| 世界里看不出设施的状态 | 停工只有一个闪烁的“!” | 停工时头顶气泡里是原因图标（缺人、缺饭、满仓……），2 级起屋顶插小旗 |

各面板现在的样子：

- **背包（Tab）**：两栏模板。没木筏时右栏是选中物品的大图卡（名字、用途）；有木筏时右栏是货舱，岛上灰着并标“到码头边的木筏旁才能搬”。底栏：选中的东西和“吃 / 放到货舱”。
- **储物箱**：左背包、右仓库格（格子上沿细条是数量 / 上限）。底栏：选中的东西、“放进仓库 / 取出 / 喝”。
- **木筏**：分页“货舱 / 改造”。货舱页同背包；改造页是建筑详情（木筏的图、24 格 → 30 格、材料格）。
- **工作台**：左边配方格（做不了的暗），右边选中配方的大图、时间、原料格 → 产物格，底栏“制作”和做不了的原因。
- **设施**：见上表；分页“生产 / 培训（下一阶段开放）”。
- **灯塔**：建筑详情。照亮范围画成一张小圆图 + “照亮 N 格”；没修的有材料格和“修灯塔”。
- **对话**：大头像 + 对白 + “需要”的图标格（已交 / 要多少，下面“身上 N”），底栏“交付”。
- **残骸**：残骸的图 + 零件格（装好的打勾、背包里有的亮、缺的暗），底栏“修理：下一阶段开放”。
- **帮助**：分页“按键”（键帽表）/“规则”（文字）。**海图**：海图放大到填满面板，图例在底栏。**菜单**：按钮居中。
- **新配方弹窗**：原料格 → 箭头 → 产物格。

## 三点五、岛上存放和昨日收成

负责人的反馈：“淡水作为唯一一种拿不走的物品，可以单独一块，可以喝或者装杯”；“仓库能存很多组，但生产上限就一组，逻辑上不合理”；“加昨日收成”。决定：储物箱改成格子 + 堆叠，随岛升级变多；设施旁加暂存箱；淡水有自己的水缸，容量随升级变大。

| 东西 | 现在 |
| --- | --- |
| 储物箱 | 和背包同一套格子 + 堆叠（原料 20 / 格，能吃喝的 10 / 格）。主岛 24 格；网络岛 1/2/3 级 12/18/24 格；加建仓库 +6 格 |
| 水缸 | 淡水不占格子，单独一条水位条，“喝”“装杯”（要会装杯、有空杯子）。主岛 60；网络岛 30/60/90；加建仓库 +30 |
| 设施暂存箱 | 产物先放这里，每级 2/3/4 格，满了停工（头顶气泡是箱子图标）。在设施面板里“拿到背包”“全部放进仓库”，点格子拿一格。产淡水的设施直接进水缸，水缸满了停工 |
| 吃饭 | 岛民先从储物箱 / 水缸拿，不够再拿暂存箱里的 |
| 昨日收成 | 每天早上 06:00 结算前一天：每座网络岛一行（岛名、等级星、产出格、三顿饭的碗：吃饱冒热气 / 凑合不冒 / 断供空碗），底栏合计。时间暂停，Esc / Enter / E 关闭。一整天什么都没产就不出 |
| 文字 | 帮助、提示卡、淡水和杯子的说明都改成新的说法 |

## 四、下一步

### 4.1 整体顺序

1. **负责人试玩全程**（可以从石头岛开始，也可以用调试面板的里程碑预设跳到 B、C、D 段），按反馈改。
2. 数值：B 段以后的请求数量、订单、升级价格没经过真人试玩，只保证自动通关能走完。
3. 画面上的“关键时刻”：获救的人走过来、灯塔修好时光圈扫开、设施升级换外形。
4. 英文版逐句润色；音乐。

### 4.2 还没做的（细节）

- 关键时刻的镜头：获救时人物走到玩家身边；修好灯塔时光圈扫开、雾退去；设施每级换一张更大的精灵（现在只多小旗）。
- 运输线的高级设置（优先级、保留量、目标库存）规则层有，界面还没放（飞行员升级后才解锁）。
- 运输线的路线只能新开 / 撤销，不能改货；要改就撤销再开。
- 在设施面板里手动分配工人。
- 提示卡（第一次出海、第一座网络岛……）仍是一段文字。
- 触屏：手机竖屏还是按横屏比例缩小；面板里的格子要点着用（没有长按详情）。
- 鼠标停在格子上才有详情；键盘选格子还没做。
- 音乐。

### 4.3 需要负责人决定的

- 画面放多大合适：现在一屏约 400 游戏像素宽（`VIEW_FIT.targetW`）。
- 自动入库机、建设地基、运输木筏、订单、进出口局升级的价格（`config/balance.ts`）。
- 同伴获救后默认留在原岛，还是默认跟上船。
- 音效的风格和音量（`config/audio.ts`）；要不要背景音乐。
- 运输木筏只在主岛船坞造、船员在船坞培训——这是为“一个功能一个建筑”做的改动（文字版在任何网络岛都能造），要不要保留。
