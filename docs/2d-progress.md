## 三、已知问题（最新一轮反馈，待改）

负责人原话的要点：“还缺 `<g>杯子×1</g>` 直接显示了代码”；“岛屿产能升级的界面没有主次、看不清楚、很难看懂”；“所有 UI 忽上忽下，UI 总体大小应该恒定”；“星露谷的界面是统一的，类似功能的页面一致，是画面 UI 驱动而不是文字驱动；你现在还是文字驱动的”；“作为一个独立的游戏好好想想怎么更有趣、更让玩家读懂”。

### 1. 显示了 `<g>` 标记（bug）

- 原因：文字版的词典把强调写成 `<g>…</g>`（`zh.ts` 里 101 处），文字版用 `<Rich>` 解析；2D 有几处直接用 `tm()` 当纯文字放进界面。
- 出现的位置：`ui/panels/Panels.tsx:88`（制作缺料，“还缺 `<g>杯子×1</g>`”）、`ui/panels/SeaPanels.tsx:93`（交付需求）、`ui/hud/WorldLayer.tsx:94,103,104`（动作条、按键提示、做不了的原因）、`ui/panels/IslandPanels.tsx:135`（设施名）。
- 更深的问题：这说明 2D 界面还在沿用文字版的“一句话说明一切”。缺料、需求、成本本来应该是**图标 + 数量**，不该是一句带标记的话。

### 2. 界面是文字驱动的

- 设施面板是一列“标签：文字”的行（产出、工人、吃饭、升级条件、花费、下一级收益），全是同样大小的字，没有主次。
- 升级规则写成一句话（“连续吃饱 6 顿后可以升级”），进度写成“3/6”，花费写成“木头×15、鱼×6”——全部应该是画出来的：6 个碗（吃饱的亮）、材料图标格（够的亮、不够的暗加红字）、一个大的“升级”按钮。
- 制作面板、交付面板、木筏改造也一样：原料和需求是文字列表。
- 日志、提示卡、目标卡字多。

### 3. 面板大小不恒定、同类页面不一致

- `Panel` 有普通和 `wide` 两种宽度，高度随内容变（`max-height` 封顶），开不同面板、内容多少不同时外框忽大忽小、标题位置跳动。
- 同类功能的布局各写一套：储物箱是“背包 | 仓库”两栏列表，木筏是“背包 | 货舱”两栏格子，制作是一行行配方，设施是一列文字行。
- 按钮、标题、小字的样式没有统一的层级。

### 4. 读不懂、不够有趣（设计层面）

- 玩家不知道设施为什么停、升级后会变成什么样；数字变化在世界里看不见（设施升级后外形不变）。
- 救人、交付、修灯塔这些“高光时刻”只有一条日志，没有画面上的反馈。
- 海上“雾退开”是唯一的探索奖励；漂流物和事件只是数字。

## 四、下一步

### 4.1 整体顺序

1. **界面重做（这一轮，插在 M3 前）**：先定统一的面板框架和视觉规范，再逐个面板改成画面驱动。改完停下给负责人试玩。
2. **可读性和趣味的小改动**（与界面重做一起或紧接着）：世界里的反馈（设施随等级换外形、获救 / 修灯塔的画面时刻）。
3. **M3 救人**：专门地图、获救弹窗、人物面板、随船人员、对话系统、培训入口。
4. M4、M5 按 `docs/2d-design.md`。

### 4.2 界面重做的细节计划

**A. 先修 bug，并从根上断掉文字版的写法**

- 界面不再显示任何带 `<g>` 的句子。缺料、需求、成本、收益统一改成结构化数据（`{ item, have, need }[]`），由一个 `<Cost>` 组件画成图标格：图标 + “有 / 要”，不够的格子变暗、数字用警告色。
- 按键提示、动作条、做不了的原因用短词（“缺斧头”“背包满”），不用整句；需要强调的东西用图标而不是标记。
- 加一个测试：遍历界面会用到的词典键（`ui.*`、`hint.*`、`act.*` 之类），不允许出现 `<g>` 等标记；剧情、日志、对白仍可用 `<Rich>`。
- 把 2D 界面引用的所有文字版字符串过一遍：要么改成 2D 的说法，要么删掉。

**B. 统一的面板框架（大小恒定）**

- 只有一种面板尺寸：固定宽高（以 480 × 270 画布为基准约 320 × 200，随 `--k` 缩放），内容多就在内部滚动，内容少也不缩。打开任何面板，外框、标题栏、关闭按钮的位置都一样。
- 面板分三块固定区域：标题栏（图标 + 名字 + 等级 / 副标题），主区，底部操作栏（主按钮永远在右下同一个位置，带按键提示，比如“E 升级”“Enter 制作”）。
- 同类页面用同一个布局模板：
  - **两栏搬运**（储物箱、木筏货舱、以后的船坞 / 交付箱）：左“背包”格子，右“容器”格子，点格子搬过去；容器是“每种有上限”的仓库时，右栏也画成格子，格子下面写“数量/上限”。
  - **配方列表**（工作台、以后的厨房 / 学堂）：左列是配方图标网格，右侧是选中配方的大图、原料图标格、产出、按钮。
  - **建筑详情**（设施、灯塔、以后的船坞）：上半是“它现在在做什么”的图（产物大图标 + 进度条 + 工人头像），下半是“升级”卡。
  - **对话 / 交付**（村民、获救的人）：头像 + 一句话 + 需求图标格 + 交付按钮。
- 字号只有三档（标题、正文、小字），颜色层级固定（主信息亮、次要暗、警告用一个颜色），写进 `global.css` 的变量和 `docs/2d-tech.md`。

**C. 设施和升级面板（负责人点名“没有主次”）**

- 主次：第一眼看到“产物 + 每小时多少 + 进度条”，第二眼看到“为什么停了”（大的 “!” 图标 + 短词），第三眼才是升级。
- 升级卡：左边是“当前等级 → 下一级”的两个小图（设施外形、产量、上限、人数各一个图标 + 数字的对比），中间是两个条件——“连续吃饱”画成 6 个碗（吃饱的亮），“材料”画成图标格；两个都满足时右下的“升级”按钮亮起。
- 工人画成头像格（有人的格子是头像、空位是虚线框），一眼看出还能放几个人。
- 设施在世界里随等级换外形（至少大小 / 装饰不同），头顶进度条旁边显示等级小星。

**D. HUD 和提示**

- HUD 四角的尺寸固定，内容变化不挤动别的元素（已有规范，再检查目标卡和日志）。
- 目标卡：一行图标 + 短句 + 距离箭头，详情放到 J 日志。
- 提示卡、介绍卡字数上限（比如 2 行），超出的放进帮助。

**E. 可读性和趣味（建议，需要负责人确认的标了“问”）**

- 关键时刻有画面：获救时人物从岛上走到玩家身边、全屏弹窗带头像；修好灯塔时光圈扫开、雾退去的镜头；设施升级时换外形 + 烟花式粒子。
- 停工原因在世界里可见：设施头顶的 “!” 换成具体图标（缺人画小人、缺粮画碗、满仓画箱子）。
- 海上探索多一些可看的东西：漂流物有不同外形、远处能看到岛的剪影引导方向。（问：是否加入海鸟 / 鱼群指示渔场这类“读海”玩法）
- 每天早上一张“昨天的收成”小结卡：各岛产了什么、谁吃饱了，用图标列出来，代替日志里一串文字。（问：要不要）

### 4.3 验收标准（界面重做）

- 界面上任何地方不出现 `<g>` 等标记（有测试）。
- 打开任意两个面板，外框大小和标题、关闭、主按钮位置完全一样（冒烟测试截图对比）。
- 设施、制作、交付、木筏改造的“需要什么”全部是图标格，不靠读句子。
- 手机宽度（390 × 844）下面板占满屏幕、内部滚动，不挡关键操作。
- `npm test`、`npm run build`、`npm run test:smoke` 通过，截图发给负责人。
